# `@cldmv/node-android-tv-remote` v2.2.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `release/2.2.0`

---

## Overview

Version 2.2.0 moves the package to the CLDMV library layout with a tsup build, moves the runtime dependency `@devicefarmer/adbkit` to its new major 4, and fixes two long-standing bugs: `waitBootComplete(timeout)` now actually stops waiting at its timeout, and `screencap()` with a `filepath` no longer reports the file saved before it is written.

The supported Node.js range changes: `engines.node` goes from `>=20.9.0` to `>=22.22.0`, and `@devicefarmer/adbkit` 4 itself requires Node.js 22.12 or later. That is a real requirement change even though it ships in a minor release; see [Breaking Changes](#-breaking-changes) and the upgrade notes. The exported API (`createRemote`, `createAndroidTVRemote` and the default export, from both `import` and `require()`) is unchanged.

---

## 💥 Breaking Changes

### Node.js `>=22.22.0` is now required ([#81](https://github.com/CLDMV/node-android-tv-remote/pull/81))

`engines.node` was `>=20.9.0` in v2.1.9 (set by `sharp`), with `require()` documented as needing `^20.19.0` or `>=22.12.0`. Both are now `>=22.22.0`. The new build toolchain no longer runs on Node.js 20 (tsup 9 alone declares `^22.18.0 || ^24.11.0 || >=26.0.0`), and `@devicefarmer/adbkit` 4 declares `>= 22.12`, so Node.js 20 is no longer supported at runtime either. The floor is set to 22.22.0, the oldest version the CI and publish matrices now test. The `ERR_REQUIRE_ESM` message that `require()` throws on a Node.js without `require(esm)` now names `>=22.22.0`.

npm prints an `EBADENGINE` warning when installing on an older Node.js, and the install fails when `engine-strict` is set.

### `waitBootComplete()` now rejects at its timeout ([#84](https://github.com/CLDMV/node-android-tv-remote/pull/84), fixes [#85](https://github.com/CLDMV/node-android-tv-remote/issues/85))

This is a bug fix, listed here because it changes what a caller sees. `waitBootComplete(timeout = 60000)` documented a timeout but never passed it on, so the call waited until the device finished booting, however long that took. See [Bug Fixes](#-bug-fixes) for the details.

## 🐛 Bug Fixes

### `waitBootComplete(timeout)` honors its timeout ([#84](https://github.com/CLDMV/node-android-tv-remote/pull/84), fixes [#85](https://github.com/CLDMV/node-android-tv-remote/issues/85))

The remote now hands adbkit 4 an `AbortSignal.timeout(timeout)`. When it fires, adbkit closes the connection and rejects with a `TimeoutError`; the remote logs the existing "Boot completion timeout after …ms" message, emits the error, and rejects. A call with no argument now gives up after the documented 60 seconds instead of waiting indefinitely.

### `screencap()` finishes writing a resized screenshot before reporting it saved ([#84](https://github.com/CLDMV/node-android-tv-remote/pull/84), fixes [#86](https://github.com/CLDMV/node-android-tv-remote/issues/86))

With a `filepath` (and optionally `width` / `height`), the background save ended the file stream and emitted `screencap-saved` and `screencap-complete` straight away, before the data reached the file, and the file stream had no `error` listener. The capture, resize and file write now run through `stream/promises` `pipeline()`: the two events fire, and `lastScreencapData` is set, only after the file is fully written. A capture, resize or write failure tears the whole pipeline down and is reported as a `screencap` error with no completion events.

## ✨ Features

### Library layout: `src/` entries and a tsup build ([#81](https://github.com/CLDMV/node-android-tv-remote/pull/81), fixes [#75](https://github.com/CLDMV/node-android-tv-remote/issues/75))

The hand-written root `index.mjs` / `index.cjs` moved to `src/index.mjs` / `src/index.cjs`, and `build` is now tsup (`tsup.config.mjs`) instead of an `echo` stub:

- `dist/index.mjs` is a minified ESM bundle of `src/index.mjs`, with names and `node:` specifiers kept. The keycode, keyboard and remote-key JSON tables are inlined. The runtime dependencies (`@devicefarmer/adbkit`, `sharp`) stay external.
- `dist/index.cjs` is not a second bundle. It is a verbatim copy of `src/index.cjs`, the thin wrapper that loads `./index.mjs` through Node's synchronous `require(esm)` and keeps the historical CommonJS shape (`module.exports` is `createRemote`, with `createRemote`, `createAndroidTVRemote` and `default` on it).

`main` / `module` point at `dist/`, `exports` adds `./package.json`, and `prepack` runs the build so `dist/` is never committed. The published files are now `dist/` (without source maps) and `scripts/postinstall.mjs`, which still runs on install to check for `adb`. `src/` and the other two helper scripts are no longer published: `scripts/setup-device.mjs` and `scripts/wake-tv.mjs` import `src/`, so they are checkout tools (`npm run setup-device` in a clone of this repository).

### `node-android-tv-remote-dev` export condition ([#81](https://github.com/CLDMV/node-android-tv-remote/pull/81))

The `"."` export carries a `node-android-tv-remote-dev` condition that points `import` and `require` at `src/`. In a checkout, `node --conditions=node-android-tv-remote-dev` runs the unbuilt source; without it the package resolves to `dist/`, which `npm run build` produces. Installed copies only ship `dist/`.

## Upgrade notes

- **Node.js `>=22.22.0` is required.** Upgrade Node.js before upgrading the package. On Node.js 20, stay on [v2.1.9](./v2.1.9.md).
- `waitBootComplete()` now rejects once its timeout (60 seconds by default) passes. A caller that relied on it waiting indefinitely for a slow boot should pass a larger timeout and handle the rejection.
- `screencap-saved` and `screencap-complete` now fire after the file is on disk, and a write failure arrives as a `screencap` error. Code that worked around the early events (for example by polling for the file) can drop the workaround.
- The exported API is unchanged for both `import` and `require()`. Code that reached into `src/` or `scripts/setup-device.mjs` / `scripts/wake-tv.mjs` inside the installed package must stop doing so; those files are no longer published.
