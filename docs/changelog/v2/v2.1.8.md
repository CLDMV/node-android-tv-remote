# @cldmv/node-android-tv-remote v2.1.8 Changelog

**Release Date**: October 2026
**Release Type**: Patch
**Branch**: `release/2.1.8`

---

## Overview

Version 2.1.8 makes remotes independent of each other and stops an unheard `error` event from crashing the process. Each remote now has its own event emitter, so two TVs no longer see each other's events. When no `error` listener is attached, an error is logged instead of thrown, and the failing call still reports it. It also restores `npm run setup-device`, which had been broken since v2.1.0, and relicenses the package under Apache-2.0.

---

## 🐛 Bug Fixes

### Each remote has its own event emitter ([#46](https://github.com/CLDMV/node-android-tv-remote/pull/46), fixes [#43](https://github.com/CLDMV/node-android-tv-remote/issues/43))

The event emitter and its helper functions were created once at module level and shared by every remote returned by `createRemote()`. With two TVs, listeners on one remote received the other remote's connect, disconnect, log and error events, and `off()` on one affected the other. Every remote now gets its own emitter.

### An `error` with no listener no longer crashes the process ([#46](https://github.com/CLDMV/node-android-tv-remote/pull/46), fixes [#44](https://github.com/CLDMV/node-android-tv-remote/issues/44))

The remote is an event emitter, and Node.js throws when `error` is emitted with no listener. Even a failed auto-connect inside `createRemote()`, before the caller could attach a listener, crashed the process. Now `error` is emitted only when a listener is attached. Otherwise the error goes out as a `log` event with level `"error"` (the `Error` is in `data.error`) and to `NODE_DEBUG=android-tv-remote`. The failing call still reports it: commands reject and `initPromise` rejects. A failed auto-connect is no longer an unhandled promise rejection for callers who never await `initPromise`. `connect()` and `disconnect()` still resolve with the `Error` rather than rejecting, as before.

### `npm run setup-device` works again ([#45](https://github.com/CLDMV/node-android-tv-remote/pull/45), fixes [#42](https://github.com/CLDMV/node-android-tv-remote/issues/42))

`scripts/setup-device.mjs` imported `src/lib/adb/setup.mjs`, which was deleted in v2.1.0, so the script failed with a module-not-found error, and it was still published. It now runs the setup steps through the v2 remote: connect, apply the keep-awake settings with `setSettings`, wake the device with `ensureAwake`, go to the home screen, and always disconnect, even when a step fails. All three scripts in `scripts/` now run their command only when executed directly and export `main()`, so importing them has no side effects.

The package is relicensed from MIT to Apache-2.0 ([#41](https://github.com/CLDMV/node-android-tv-remote/pull/41)). The repository now has a `LICENSE` file; before this it had none, although `package.json` declared MIT.

## 🧪 Tests

- `tests/scripts.test.vitest.mjs` imports every file under `scripts/`, so a dangling import fails CI, and tests the setup flow against a fake remote.
- `tests/events.test.vitest.mjs` mocks `@devicefarmer/adbkit`, so no real ADB or network connections are made. It checks that two remotes are independent, and that errors with and without a listener are reported correctly for `connect`, `keyboard.key` and auto-connect.
- Line coverage rises from about 13% to about 23%.

## Upgrade notes

- No breaking changes: drop-in for [v2.1.7](./v2.1.7.md).
- If you ran several remotes and relied on one remote's listeners also receiving another remote's events, that was the bug fixed here; attach listeners to each remote.
- Code that kept the process alive only because an unheard `error` crashed it no longer crashes: listen for `error`, or for `log` events with level `"error"`, if you want to act on failures without awaiting the call.
- The license is now Apache-2.0.
