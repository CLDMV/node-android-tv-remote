# @cldmv/node-android-tv-remote v2.1.7 Changelog

**Release Date**: October 2026
**Release Type**: Patch

---

## Overview

Version 2.1.7 fixes the CommonJS entry. `index.cjs` now loads the ESM build directly through Node's synchronous `require(esm)`, fails with a clear, actionable message on Node.js versions that can't do that, and exports `createAndroidTVRemote` alongside `createRemote`, so `require()` and `import` expose the same factories. The ESM entry and the remote API are unchanged.

---

## 🐛 Bug Fixes

### CommonJS entry requires the ESM build directly and fails clearly without `require(esm)` ([#39](https://github.com/CLDMV/node-android-tv-remote/pull/39))

`index.cjs` used to load `index.mjs` through a `createRequire()` indirection, which on Node.js without `require(esm)` failed with a bare `ERR_REQUIRE_ESM` that didn't say what to do. It now calls `require("./index.mjs")` directly and, before that, checks `process.features.require_module`: on Node.js older than ^20.19.0 / >=22.12.0 it throws an `ERR_REQUIRE_ESM` error that names the required versions and points to `import()`.

### `createAndroidTVRemote` exported from CommonJS ([#39](https://github.com/CLDMV/node-android-tv-remote/pull/39))

The ESM entry has exported `createAndroidTVRemote` since v2.0.0, but the CommonJS entry only exposed `createRemote` (as the module itself, `.createRemote` and `.default`). It now exports `createAndroidTVRemote` too:

```js
const { createAndroidTVRemote } = require("@cldmv/node-android-tv-remote");

const remote = await createAndroidTVRemote({ ip: "192.168.1.100" });
```

## 🔧 CI & tooling

- New `tests/cjs/entry.test.cjs` (`node:test`), run after Vitest by `npm test` and `npm run coverage` through a new `test:cjs` script. It checks that `require()` exposes the same factories as `import` and that the Node.js version check fires when `require(esm)` is unavailable.

## Upgrade notes

- No breaking changes — drop-in for v2.1.6. CommonJS consumers need Node.js ^20.19.0 or >=22.12.0, as they already did; on older Node.js the error message is now explicit, and `import()` remains the way to load the package there.
- v2.1.1 through v2.1.7 were released on GitHub but have not reached npm, where the latest published version is still v2.1.0. Upgrading from npm's v2.1.0 picks up everything in between, including the Node.js 20.9.0 floor from v2.1.1.
