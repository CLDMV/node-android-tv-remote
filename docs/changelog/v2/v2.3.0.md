# `@cldmv/node-android-tv-remote` v2.3.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `release/2.3.0`

---

## Overview

Version 2.3.0 replaces `@devicefarmer/adbkit` with `@cldmv/droidsock`, which speaks the ADB protocol itself. The `adb` command-line tool and its server are no longer needed to drive a device, and the install-time check for `adb` is gone. Keeping the connection alive also moves to droidsock: `maintainConnection` now turns on its heartbeat and its automatic reconnect with backoff, in place of the remote's own heartbeat timer and periodic `adb devices` check.

The exported API (`createRemote`, `createAndroidTVRemote` and the default export, from both `import` and `require()`) is unchanged. `engines.node` rises from `>=22.12.0` to `>=22.15.0`, the floor droidsock declares. See [Requirements](#-requirements) and the upgrade notes.

---

## 📦 Requirements

### Node.js `>=22.15.0` is now required ([#95](https://github.com/CLDMV/node-android-tv-remote/pull/95))

`engines.node` goes from `>=22.12.0` to `>=22.15.0`, matching `@cldmv/droidsock` 2. `require()` loads the ESM build through Node's `require(esm)`, which runs without warnings on that floor, so the message `require()` throws on an older Node.js now names `>=22.15.0`.

### The `adb` binary is optional ([#95](https://github.com/CLDMV/node-android-tv-remote/pull/95))

The remote no longer shells out to `adb` or needs its server running. Install `adb` only for your own use, such as the `setup-device` steps in the README. The `postinstall` script that printed install instructions when `adb` was missing has been removed, along with `scripts/postinstall.mjs` in the published package.

---

## ⚠️ Behavior changes

### Connection upkeep comes from droidsock ([#95](https://github.com/CLDMV/node-android-tv-remote/pull/95))

With `maintainConnection` on (the default), the remote enables droidsock's heartbeat (every `heartbeatInterval` ms, 20 seconds by default) and its automatic reconnect with backoff. A dropped connection is noticed by the socket and the heartbeat and reconnected without waiting for a polling interval. Reconnect attempts, successful reconnects and giving up are reported through the `log` channel, and the connected state follows the socket.

- `connectionCheckInterval` is deprecated and ignored.
- `getConnectionStatus()` returns `"connected"` or `"disconnected"`; it no longer returns `"unknown"`.
- With `autoConnect` off, a command on a remote that never connected rejects with `Device not connected`.

### Calls without a droidsock equivalent run through `shell` ([#95](https://github.com/CLDMV/node-android-tv-remote/pull/95))

`screencap()` captures the PNG in memory over `shell`, and `waitBootComplete()` polls `sys.boot_completed`. Each poll gets only the time left before the timeout, so a hung device can't keep `waitBootComplete()` waiting past it.

## 🧪 Tests

- The adb-client and event tests use a droidsock mock, and a new test runs the real droidsock against a fake device on a local socket ([#95](https://github.com/CLDMV/node-android-tv-remote/pull/95)).
- `npm run test:dist` builds the package and runs the suite against `dist/`; `npm test` now includes it. The tests import the package by name, and a resolve test checks each run loaded the tree it meant to ([#96](https://github.com/CLDMV/node-android-tv-remote/pull/96)).
- The vitest config sets the `node-android-tv-remote-dev` condition with `devCondition()` from `@cldmv/configs`. The `test.nodeOptions` it used before isn't a Vitest option, so the condition never reached the test workers ([#93](https://github.com/CLDMV/node-android-tv-remote/pull/93)).

## Upgrade notes

- **Node.js `>=22.15.0` is required.** On Node.js 22.12 to 22.14, stay on [v2.2.1](./v2.2.1.md).
- You can uninstall `adb` if nothing else needs it.
- Drop `connectionCheckInterval` from your config; it has no effect. Use `heartbeatInterval` to tune how fast a dead connection is noticed.
- Code that checked `getConnectionStatus()` for `"unknown"` can drop that branch.
